# TD-023: `Distribution.equals` and `Doc.equals` compare nothing, so any two instances are equal

## Status

Open. Found while implementing [ADR-021](../adr/021-effective-jira-display-name.md); **not** caused
by it. Amplifies [TD-022](022-jira-component-version-range-equality-drops-components.md).

## Symptom

Two components with completely different distributions — different GAV, different docker image,
different security groups — compare **equal** as `Distribution` values, and hash the same. Any code
that puts them in a `Set`, uses them as a `Map` key, or short-circuits on `equals` treats them as
interchangeable.

## Mechanism

`component-resolver-api/src/main/groovy/.../escrow/model/Distribution.groovy` carries Groovy's
`@EqualsAndHashCode`, and **every field is declared `private final`**:

```groovy
@EqualsAndHashCode
class Distribution {
    @JsonProperty private final boolean explicit
    @JsonProperty private final String GAV
    @JsonProperty private SecurityGroups securityGroups
    // …
}
```

`@EqualsAndHashCode` compares *properties*, not fields, and its `includeFields` option defaults to
`false`. In Groovy a **private field is not a property** — properties are the ones declared without
an access modifier. The class therefore has no properties for the transform to compare, and the
generated methods degenerate.

Confirmed in the generated bytecode rather than inferred from the source:

```
javap -p -c .../escrow/model/Distribution.class
  equals():   null check → is() → instanceof → canEqual.   No field read.
  hashCode(): no reference to getGAV / getDocker / getSecurityGroups / getDEB / getRPM.
```

The `@JsonProperty` annotations are a red herring — they drive Jackson, not the Groovy AST
transform, so serialization is complete while equality is empty.

## Why it matters

`JiraComponentVersionRange.equals` compares `versionRange`, `jiraComponent`, `distribution` and
`vcsSettings`. Because the `distribution` term is vacuous, that equality reduces to three fields —
so TD-022's cross-component collapse reaches **much** further than its own description suggests: it
catches components that merely share a Jira project, a version range and a VCS root, whatever they
ship.

This is exactly what the ADR-021 compat investigation ran into. The two components the candidate
recovered have a baseline twin that matches on every term of the real contract and differs only in
`distribution` — which production never compared. `Adr021RangeRecovery` had to model the real
(degenerate) contract to reach the right verdict, and reports the distribution divergence as a note
rather than hiding it.

## Fix

Add `includeFields = true` to the annotation, or replace it with an explicit `equals`/`hashCode` over
the seven fields. Either is a one-line change with a wide blast radius, so it needs its own compat
run: today's responses depend on the degenerate behaviour, and fixing it will change which elements
survive the `Set` — the same class of change as TD-022 and best sequenced with it.

## Audit of the sibling models (done)

Every Groovy class in `escrow/model` was measured the same way — counting field and getter
references inside the generated `equals`, with `Distribution` as the known-bad control:

| class | annotated | own `equals` | field refs in `equals` | verdict |
|---|---|---|---|---|
| `Distribution` | yes | no | 3 (all `canEqual`/`is`) | **degenerate** |
| `Doc` | yes | no | 3 (all `canEqual`/`is`) | **degenerate — same defect** |
| `Tool` | yes | no | 13 | fine (its properties are not private) |
| `Dependency` | yes | yes | 14 | fine |
| `BuildParameters` | yes | yes | 26 | fine |
| `VCSSettings`, `VersionControlSystemRoot` | no | yes | hand-written | fine |

So the defect is **`Distribution` and `Doc`**, and only those two. Both carry `@EqualsAndHashCode`
over `private final` fields and declare no `equals` of their own. `Doc`'s blast radius is smaller —
it is not a term of `JiraComponentVersionRange.equals` — but it is the same bug and should be fixed
in the same change.

## Risk if left

Silent, data-dependent equality that is wrong in the permissive direction. Nothing fails; entries
disappear. It also makes every equality-based assertion over these models weaker than it reads,
including test fixtures that appear to pin a distribution and in fact pin nothing.
